    Conditions: salary > 60000, dept = 'Sales', combine with AND / OR / NOT and parentheses. Text values need quotes. Deleting an operator promotes whatever was inside it, so you can peel a query apart layer by layer.

    Tab to complete: type proj in the Type it box and press Tab to get π_{}() with the cursor in the braces. Inside braces it suggests attribute names, outside them relation names; Tab with no menu open jumps to the next empty spot, so proj ⇥ ena ⇥ ⇥ Emp ⇥ writes the whole query. ↑↓ pick, Esc dismisses, Enter checks.

    Aggregation: ℱ has two boxes — grouping attributes on its left, functions on its right: dept ℱ COUNT(eid), AVG(salary) gives one row per department. Leave the left box empty to summarise everything in a single row. Functions are COUNT, SUM, AVG, MIN and MAX; the output columns are named after them (COUNT_eid), so σ can filter on them the way SQL's HAVING does. Type group for the ℱ.

    Typing: the Type it box takes standard notation — π_{ename}(σ_{salary > 60000}(Employee)) — and the canvas follows along as you type. No Greek keyboard needed: project, select, rename, union, intersect, minus, join, product and divide all work, as do |><|, *, - and /. Square brackets are accepted in place of braces: project[ename](Employee). A ? stands for a slot you have not filled in yet.
