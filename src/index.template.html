    Conditions: salary > 60000, dept = 'Sales', combine with
    AND / OR / NOT and parentheses. Text values need quotes.
    Deleting an operator promotes whatever was inside it, so you can peel a query apart layer by layer.
    Result collapses from its header if you would rather work without seeing the answer as you build it.
  
      
  
      
    Tab to complete: type proj in the Type it box and press
    Tab to get π_{}() with the cursor in the braces. Inside braces it
    suggests attribute names, outside them relation names; Tab with no menu open jumps to
    the next empty spot, so proj ⇥ ena ⇥ ⇥ Emp ⇥ writes the
    whole query. ↑↓ pick, Esc dismisses, Enter checks.
  
      
  
      
    Aggregation: ℱ has two boxes — grouping attributes on its
    left, functions on its right: dept ℱ COUNT(eid), AVG(salary) gives one row
    per department. Leave the left box empty to summarise everything in a single row. Functions are
    COUNT, SUM, AVG, MIN and MAX;
    the output columns are named after them (COUNT_eid), so σ can filter on them the
    way SQL's HAVING does. Type group for the ℱ.
  
      
  
      
    SQL mode: the switch above the canvas changes the language, not the question. Your answer is
    checked by running it, so any query that returns the right table is right — but SQL keeps duplicate
    rows, so DISTINCT is yours to remember. Supported: SELECT/DISTINCT,
    FROM with aliases and JOIN … ON / USING / NATURAL JOIN,
    WHERE, GROUP BY, HAVING, ORDER BY,
    LIMIT, UNION / INTERSECT / EXCEPT, and subqueries
    with IN, EXISTS or a single value — correlated to the outer query or not.
    Tab completes clauses, table names and column names; Ctrl+Enter checks
    your answer. Levels 38 and up are SQL only: the algebra has no way to ask them.
  
      
  
      
    Switching carries your query with it. Toggle to SQL and the tree you built is written out
    as a query; toggle back and your query is read back as a tree. Whatever you wrote yourself is
    never overwritten — the query only crosses when the other side is empty or still holds what it
    was handed. Some queries cannot cross, and the game says which part is the problem:
    EXISTS and subqueries inside a condition, ORDER BY, LIMIT,
    computed columns and COUNT(DISTINCT …) have no counterpart in the algebra — that
    refusal is the lesson. A query that came across counts as help, so the level is worth ✓ rather
    than ★ until you write it yourself.
  
      
  
      
    Typing: the Type it box takes standard notation —
    π_{ename}(σ_{salary > 60000}(Employee)) — and the canvas follows along as you type.
    No Greek keyboard needed: project, select, rename,
    union, intersect, minus, join,
    product and divide all work, as do |><|,
    *, - and /. Square brackets are accepted in place of
    braces: project[ename](Employee). A ? stands for a slot you have not
    filled in yet.
